🧠 Key Concepts

count() vs Collectors.counting() — When to Use Each

Both count elements, but in different contexts. .count() is a terminal operation called directly on a stream to get the total number of elements in it. Collectors.counting() is used specifically as a downstream collector — most commonly inside groupingBy(), where you want to know the count WITHIN each group, not the total across the whole stream.

Collectors.groupingBy() — Grouping by a Shared Property

groupingBy() takes a classifier function (a way of computing a "key" for each element) and groups elements sharing the same key together. The result is a Map<K, List<T>> — the key type depends on your classifier, and the value is a List of all elements that share that key.

Example: Grouping City Names by Length

Given a list of city names, grouping by String::length produces a Map<Integer, List<String>> — e.g. all 5-letter cities together, all 6-letter cities together, and so on. This is described as one of the most heavily used Stream API operations in real interview and practical scenarios.

Collectors.partitioningBy() — Splitting Into Exactly Two Groups

partitioningBy() is a specialized version of grouping: it takes a boolean condition (a Predicate) and always produces exactly two groups — a Map<Boolean, List<T>>, where true holds elements matching the condition, and false holds everything else.

Example: Partitioning Numbers into Even and Odd

Given a list of integers, partitioning by "is this number even" produces: true → [all even numbers], false → [all odd numbers]. If asked to "filter all the even numbers," partitioningBy() is a clean, direct way to do it — you get both groups in one pass.

groupingBy() vs partitioningBy() — The Core Distinction

groupingBy() can produce any number of groups, based on however many distinct key values exist. partitioningBy() ALWAYS produces exactly two groups (true/false) — since it's fundamentally based on a yes/no condition.

Converting a String to a Stream of Characters

Strings don't have a direct .stream() method that gives characters. The approach: input.chars() gives an IntStream of the ASCII (numeric) codes of each character — NOT the characters themselves. To get actual Character objects, apply .mapToObj(c -> (char) c), which converts each int back into a Character object.

Counting Character Occurrences — A Classic Interview Problem

Flagged as extremely likely to come up: "Count how many times each character appears in a string." The approach combines everything above: convert the string to a character stream, then use groupingBy() with Collectors.counting() as the downstream collector — grouping by the character itself, counting how many times each group's key appears.

Finding the First Non-Repeating Character — Another Classic

The problem: given a string, find the first character that appears exactly once. Example: in "SWISS", walking through — S appears multiple times, W appears once. The first character that's NOT repeated is the answer.

The indexOf() / lastIndexOf() Trick

The elegant approach demonstrated: for a given character, input.indexOf(c) gives its FIRST position; input.lastIndexOf(c) gives its LAST position. If a character appears only once, these two positions are identical. If a character repeats, the first and last positions will differ. So: filter(c -> input.indexOf(c) == input.lastIndexOf(c)) keeps only non-repeating characters, and findFirst() gives you the very first one among them.

Why This is Considered "The Easiest" Approach

The instructor explicitly noted that searching this problem online (e.g. via ChatGPT) would surface 5-6 different possible approaches — but the indexOf/lastIndexOf comparison was highlighted as the one most people find easiest to understand and remember, since it reuses two very familiar String methods in a clever way.

Finding the 2nd Highest Salary — Custom Objects

Same overall pattern as the earlier "3rd highest salary" exercise (with plain integers), but now applied to a list of custom Employee objects with name and salary attributes. Approach: sort employees by salary in descending order (using a comparator comparing salary), then skip(1) (skipping the highest), then findFirst() to get the employee with the 2nd highest salary.

The Homework — Same Duplicate Lesson, Reapplied

Deliberately assigned as homework: this initial solution breaks if two employees share the same (highest) salary — the exact same duplicate-handling issue covered in the earlier "3rd highest salary" class. The task: apply the same fix (distinct() based on salary, before sorting) so the logic correctly finds the 2nd highest DISTINCT salary, regardless of duplicates.

💻 Code Snippets / Examples

count() vs Collectors.counting():

List cities = Arrays.asList("Delhi", "Mumbai", "Bangalore", "Chennai", "Pune", "Kochi");

long total = cities.stream().count(); // simple terminal count — total elements in the stream
System.out.println(total); // 6

Collectors.groupingBy() — group cities by name length:

import java.util.*;
import java.util.stream.*;

List cities = Arrays.asList("Delhi", "Mumbai", "Bangalore", "Chennai", "Pune", "Kochi");

Map> groupedByLength = cities.stream()
        .collect(Collectors.groupingBy(String::length));

System.out.println(groupedByLength);
// {4=[Pune], 5=[Delhi, Kochi], 6=[Mumbai], 7=[Chennai], 9=[Bangalore]}

groupingBy() combined with counting() — count elements PER group:

Map countPerLength = cities.stream()
        .collect(Collectors.groupingBy(String::length, Collectors.counting()));

System.out.println(countPerLength);
// {4=1, 5=2, 6=1, 7=1, 9=1}

Collectors.partitioningBy() — split numbers into even and odd:

List numbers = Arrays.asList(10, 15, 22, 33, 40, 51, 60);

Map> partitioned = numbers.stream()
        .collect(Collectors.partitioningBy(n -> n % 2 == 0));

System.out.println(partitioned);
// {false=[15, 33, 51], true=[10, 22, 40, 60]}

List evenNumbers = partitioned.get(true);
System.out.println(evenNumbers); // [10, 22, 40, 60]

Converting a String into a stream of characters:

String input = "Hello";

// input.chars() gives an IntStream of ASCII codes: 72, 101, 108, 108, 111
Stream characterStream = input.chars()
        .mapToObj(c -> (char) c); // converts each int back into a Character object

characterStream.forEach(System.out::println); // H, e, l, l, o

Counting character occurrences — classic interview problem:

String input = "MISSISSIPPI";

Map charCounts = input.chars()
        .mapToObj(c -> (char) c)
        .collect(Collectors.groupingBy(
            Function.identity(),   // group by the character itself
            Collectors.counting()  // count occurrences within each group
        ));

System.out.println(charCounts);
// {M=1, S=4, I=4, P=2}

Finding the first non-repeating character — classic interview problem:

String input = "SWISS";

Optional firstNonRepeating = input.chars()
        .mapToObj(c -> (char) c)
        .filter(c -> input.indexOf(c) == input.lastIndexOf(c)) // occurs exactly once
        .findFirst();

System.out.println(firstNonRepeating.get()); // W

Finding the 2nd highest salary — custom Employee objects:

class Employee {
    String name;
    int salary;

    public Employee(String name, int salary) {
        this.name = name;
        this.salary = salary;
    }

    public String getName() { return name; }
    public int getSalary() { return salary; }
}
List employees = new ArrayList<>();
employees.add(new Employee("Ravi", 45000));
employees.add(new Employee("Priya", 60000));
employees.add(new Employee("Rajat", 54000));
employees.add(new Employee("Kiran", 38000));

Employee secondHighest = employees.stream()
        .sorted((e1, e2) -> Integer.compare(e2.getSalary(), e1.getSalary())) // descending
        .skip(1) // skip the highest
        .findFirst()
        .get();

System.out.println(secondHighest.getSalary()); // 54000 (Rajat)

Homework fix — handling duplicate salaries correctly:

List employees = new ArrayList<>();
employees.add(new Employee("Ravi", 60000));
employees.add(new Employee("Priya", 60000)); // duplicate highest salary
employees.add(new Employee("Rajat", 54000));
employees.add(new Employee("Kiran", 38000));

// FIX: distinct by salary value BEFORE sorting/skipping
Employee secondHighestFixed = employees.stream()
        .map(Employee::getSalary)
        .distinct()                          // remove duplicate salary VALUES first
        .sorted(Comparator.reverseOrder())    // descending
        .skip(1)
        .findFirst()
        .get();

System.out.println(secondHighestFixed); // 54000 — correctly the 2nd DISTINCT highest salary
// (Note: this version returns just the salary value; adapt further if you need
// the full Employee object with a distinct-by-salary-value guarantee.)

📌 Important Points / Common Mistakes

  • Use .count() for a simple total; use Collectors.counting() specifically as a downstream collector inside groupingBy().
  • groupingBy() → any number of groups; partitioningBy() → always exactly 2 groups (true/false).
  • String.chars() gives ASCII int codes, NOT characters — always follow with .mapToObj(c -> (char) c) to get actual Character objects.
  • groupingBy(Function.identity(), Collectors.counting()) is the standard pattern for frequency-counting problems.
  • indexOf() == lastIndexOf() is a clean, memorable trick for detecting elements that occur exactly once.
  • Always account for duplicate values when solving "Nth highest" problems — apply distinct() before sorting/skipping.
  • These three problem types (character frequency, first non-repeating character, Nth highest value) are considered near-certain interview questions — practice them until they're automatic.
