Client, Front End, Back End and Database
  • Client: a person or another system that uses the back-end system — it needn't be human.
  • Front end: the user interface (UI) the user interacts with.
  • Back end: the processing logic.
  • Database: stores and supplies data.
  • The class will focus on back-end development, with only as much front end as needed to test it.

Server Address, Application Server and localhost
  • To reach a server the client uses an address — the instructor compared it with dialling a phone number. The request reaches the server, the back-end code processes it (possibly talking to the database) and returns a response.
  • An application server hosts and runs the application continuously. You deploy the application inside it and start the server. The class will use Apache Tomcat — pronounced "Tomcat", not "Tom and Cat".
  • localhost refers to your own machine. It's the same idea as the local MySQL connection you used (localhost plus a port, 3306 as heard in class). If the service is on a remote machine, the client needs that machine's host name or IP address.
Back-End Services and Request Routing
  • The back end isn't one undifferentiated block — it holds many services, each with a job: search / product search, order (placing an order), notification (email or messages) and payment.
  • The request must make clear what action the client wants and on which data. A request that just says "water" isn't enough; a "send message" request needs the message content and the recipient, and "delete message" must invoke the delete functionality instead. Other examples: viewing order history.
  • The instructor showed that the URL/route changes as you move around an e-commerce site — different routes correspond to different functions such as order history. So the UI isn't only visual: it sends requests that tell the back end which operation to run.
HTTP and HTTPS
  • Client and server communicate over HTTP (Hypertext Transfer Protocol): the client sends an HTTP request; the server receives it, invokes the relevant Java back-end code, runs the processing logic and sends an HTTP response.
  • HTTPS: the "S" stands for secure — the communication is secured using certificates.
The Instructor's Learning Advice
  • Core Java will play a major role in back-end development.
  • Practise each day's work the same day. A 90-minute class can need several hours of setup and practice; repeating setup many times can eat days, so stay consistent instead of leaving everything for the weekend.
  • Moving from UI to back-end communication may feel hard at first — relate every concept to an e-commerce application, since you already understand searching, ordering, payment and notifications.
  • The domain differs by company (healthcare, travel, retail, banking…). Don't assume every company uses the same technology or service names: learn the general process and become adaptable instead of tightly attached to one project or tool.
Enabling Enterprise Web Development in Eclipse

The existing Eclipse installation may not be set up to create enterprise web applications, so the class enabled it in two attempts. Success check after each: can you create/see a Dynamic Web Project?

Route 1 — Spring Tools (STS) from Eclipse Marketplace

  1. Help → Eclipse Marketplace.
  2. Search for Spring Tools / Spring Tool Suite (STS) and pick the entry.
  3. Go through the installation wizard, accept the terms and finish; watch the progress indicator.
  4. Trust the certificates/content when prompted, then restart Eclipse.
  5. Check for the project options. Some students didn't see Dynamic Web Project — the enterprise web tools hadn't installed.

Route 2 — "Enterprise Java and Web Developer Tools"

  1. Help → Install New Software.
  2. Search for "Enterprise Java and Web Developer Tools" and select that entry.
  3. Continue through the confirmation screens, accept the prompts and let the install finish.
  4. Restart Eclipse, then check again for enterprise/web project capabilities, including Dynamic Web Project. Some students already had the feature — check yours first.

Fallback — a different Eclipse package

If the plugin route keeps failing, download the Eclipse package that already includes the web tooling: Eclipse IDE for Enterprise Java and Web Developers.

Troubleshooting Installation Problems

Several students hit installation or startup problems. The instructor asked them to find the actual error message rather than saying "Eclipse is not working", and to look at the error/log information to decide which of these it was:

  • Eclipse failing to start,
  • a download failure,
  • a plugin installation failure,
  • the installation stuck at some percentage, or
  • a conflict with an already-installed plugin or feature (a plugin update can cause conflicts on some systems).

He didn't establish one universal fix. Resolve the setup before the next class; if the plugin route fails, install the enterprise package directly and be ready.

💡 Added clarification:
  • Why Route 1 didn't show Dynamic Web Project (most likely): that project type comes from Eclipse's Web Tools Platform, which is what the "Enterprise Java and Web Developer Tools" feature provides; Spring Tools is separate tooling. The recording doesn't say this outright.
  • Tomcat's default port is 8080 — the instructor didn't give a number for Tomcat; the 3306 he mentioned is MySQL's.
  • Where to read the Eclipse error: Window → Show View → Error Log, or the .log file inside the workspace's .metadata folder; Help → About Eclipse IDE → Installation Details shows what is installed.
