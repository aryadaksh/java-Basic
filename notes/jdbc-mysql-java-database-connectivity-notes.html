🧠 Key Concepts

What Is JDBC? — The Bank-Statement Example

JDBC = Java Database Connectivity. Picture a backend system — the application, which means Java code. When that Java code wants to interact with databases, JDBC is involved. A database's purpose is to store data so that when the application needs it in the future, the database can provide it.

  1. The user hits a request on the system — say, for a bank statement.
  2. The application knows he wants a bank statement, and knows where the statement is: inside the database.
  3. It asks the database: "Can you please provide the bank statement for this user?" The database searches and gives it back.
  4. The backend processes the data again and gives the final statement to the user.

To show anything meaningful, applications use databases.

You Are a Database User, Not a Database Expert

There are 100+ different databases. The instructor's advice: don't try to become a database expert — you are a database user. Every database has its own language, SQL.

The Problem — Java and the Database Don't Share a Language
  • The database doesn't understand Java, and Java doesn't understand SQL.
  • That is where JDBC comes in between: "I will be helping you both."
  • JDBC allows a Java program to interact with databases — that's all. Problem simplified.
  • Analogy: when two people have no common language they need an intermediary / translator. As of now, that translator is JDBC. Inside it sits a connector.
The Driver Idea — Why Every Database Needs One
  • Connect a wireless mouse and the system first installs a driver; the driver translates the signals the mouse sends to the computer.
  • Games, sound, a digital pen — everything has a driver, installed so that the computer understands your instructions.
  • In the same way, whenever you interact with a database you need the database driver.
  • Every database vendor releases its own driver, and it is language-specific.
MySQL Connector/J — The Java Driver Is Just a JAR
  • On MySQL's website there are connectors for every language MySQL supports: .NET people install the .NET one, C++ people use the C++ one, and for Java it's Connector/J — the one we use.
  • A connector is nothing but a JAR file containing the classes that let your application interact with the database.
  • The instructor downloaded it, extracted the JAR and ran jar -tvf on it: many classes inside — one JAR doing this much work. (He remarked that a JAR can easily hold 500+ classes.)
  • That JAR is added as a dependency in whichever program uses JDBC. Remember: you already know what a dependency is and how to add one — now we use it for real.
  • It's the same story for other databases: MongoDB, Oracle, Cassandra each have a connector released by their own company, which you provide as a dependency.

🔥 The Four Steps of JDBC (Standard — Memorise)
  1. Register the driver — tell the program which driver you will use.
  2. Create the connection — your application is talking to someone who is somewhere else, so first connect to that database.
  3. Create a statement — somebody has to carry your data/query to the database.
  4. Execute the SQL — send the query and get the result.

The instructor said registering the driver "might not be required — it's optional — but better to do it". He told the class: "from today onward, every day we interact with the database."

Step 1 — Register the Driver: Class.forName(...)
  • There is a class in Java called Class (capital C — it's the name of the class itself, in the java.lang package). It has a static method forName that loads a class into memory.
  • You give it the name of the driver class. To find the name, look inside the JAR with jar -tvf: the connector contains two driver classes — a newer one under mysql/cj and an older one. Use the latest.
  • Write the name with dots, not slashes, even though the JAR listing shows slashes.
  • Class.forName throws a checked exception — ClassNotFoundException (which you know from exception handling). If the class isn't found you get it.

The first run used the older driver class: the program worked but printed a warning. Deprecated means outdated — the library is telling you to use the latest class. Step 2 — Create the Connection
  • To connect to somebody you need to know where they are and the credentials. For a database that means: the host / URL (where the database is), a username and a password.
  • Call DriverManager.getConnection(...) with those. It throws SQLException, another checked exception that forces you to handle it at compile time. In the demo the instructor simply declared throws to keep the code short (an IDE can generate the handling).
  • The URL has the form jdbc:mysql:// + host + port + database name: here localhost, port 3306, and the database we created earlier. Username root and the password set during MySQL installation.
  • You don't have to remember the jdbc:mysql://… format — copy and paste it from the reference and correct it. The instructor's advice for advanced Java: copy-paste configuration as much as possible; type only the code.
  • If the database server runs on some remote machine, give the IP address / host of that machine instead of localhost.
  • Once this line runs, your program is connected to the database.
Step 3 — Create a Statement (the Data Carrier)

We're connected, but somebody needs to carry your data/query to the database and bring data back. That carrier is the Statement: on the connection call createStatement(). What you did in the MySQL console is now done through this object.

Step 4 — Execute the Query and Read the ResultSet
  • On the statement you call an execute method. There are multiple methods depending on your requirement; to read all records the instructor used executeQuery with the same SQL you ran in the console: select * from <table>. (Copy it if you're not comfortable writing it.)
  • It always returns a ResultSet — all the returned rows are part of one object: the first record, the second record, and so on. You have to loop over it.
  • We don't know how many records there will be — two now, 10 or 1,000 tomorrow — so use rs.next() in a loop: it checks whether the next record exists.
  • Inside the loop read each column with rs.getXxx(position) chosen by the column's data type (getInt, getString, getBoolean…). The index starts from 1: in the demo table, position 1 = ID (int), 2 = item (String), 3 = price (int, as taught), 4 = status (String). If unsure of the order, run describe on the table in the console.
  • Print the values to see them. That's how you iterate a result set.

Recap of the Four Steps (Instructor's Walk-Through)
  1. Register the driver — tell the program which driver you're going to use.
  2. Create the connection — the program is now connected to the MySQL server; the server runs locally on this port, with this database. For a remote machine use its IP/host. Username and password go here.
  3. Create the statement object — somebody has to carry the data for query execution.
  4. Execute the query — a select definitely returns data, stored in the ResultSet; loop and read by index and type.
Q&A — Do We Start MySQL Ourselves?

A student wasn't sure whether MySQL had to be started. No. On a local Windows machine the MySQL server is a Windows service — it starts automatically when the computer starts and stops when it shuts down. You don't start MySQL locally.

💡 Added clarification — terms and details the lecture didn't spell out:
  • JDBC is an API, the driver is the implementation: JDBC is a set of interfaces in the java.sql package (Connection, Statement, ResultSet…) plus DriverManager. The vendor's driver (Connector/J) supplies the classes that implement them for MySQL. The lecture called JDBC the "translator" with a "connector" inside it.
  • Driver registration is usually automatic: with JDBC 4.0 and later, a driver JAR on the class path is discovered automatically, so Class.forName is often optional — matching what the instructor said. He kept it because it shows dynamic class loading.
  • Driver class names: the current MySQL 8.x driver class is com.mysql.cj.jdbc.Driver; the older com.mysql.jdbc.Driver still exists but is deprecated (it prints the warning seen in class). The transcript doesn't spell either name out clearly, so I'm inferring them.
  • Maven coordinates: the instructor said the group is "MySQL". That matches mysql:mysql-connector-java (up to 8.0.33); newer releases are published as com.mysql:mysql-connector-j. Copy the snippet from the repository site, as he said, rather than typing it.
  • Why ClassNotFoundException shows up in JDBC: the usual causes are a misspelled class name (slashes instead of dots) or the connector JAR missing from the project's dependencies.
  • executeQuery vs executeUpdate vs execute: executeQuery is for select and returns a ResultSet; executeUpdate is for insert / update / delete (and table-changing statements) and returns an int; execute is the general-purpose method. The lecture showed the first two.
  • ResultSet cursor: it starts before the first row; next() moves to the next row and returns false when there are none. Columns can be read by 1-based index (as taught) or by column name, which survives column-order changes.
  • Match the getter to the column type: the demo read price with getInt; if your column is double or decimal, use getDouble / getBigDecimal.
  • Close your resources: ResultSet, Statement and Connection should be closed — ideally with try-with-resources. The lecture skipped this to stay focused.
  • Don't build SQL by string concatenation: making the update method take id and status is the right idea, but gluing them into the SQL string opens the door to SQL injection. PreparedStatement with ? placeholders is the safe way (not covered in this lecture).
  • Credentials: the demo hard-codes the username and password for simplicity; real projects keep them in configuration, not in source code.
  • Two meanings of "driver class": the JDBC driver class (com.mysql.cj.jdbc.Driver) vs the class with main that the instructor also called "my driver class". Don't mix them up.

3. Reading data — the four steps and the ResultSet loop (OrderHistory):

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;

public class OrderHistory {

    public void getOrders() throws ClassNotFoundException, SQLException {

        // Step 1: register the driver (dynamic class loading; throws ClassNotFoundException)
        Class.forName("com.mysql.cj.jdbc.Driver");

        // Step 2: create the connection (host, port, database, username, password; throws SQLException)
        Connection con = DriverManager.getConnection(
                "jdbc:mysql://localhost:3306/first_june", "root", "your_password");

        // Step 3: create the statement - the carrier that sends the SQL
        Statement stmt = con.createStatement();

        // Step 4: execute the query - a select always gives a ResultSet
        ResultSet rs = stmt.executeQuery("select * from order_history");

        while (rs.next()) {                       // is there another record?
            int id        = rs.getInt(1);         // index starts at 1
            String item   = rs.getString(2);
            int price     = rs.getInt(3);         // price treated as an integer in class
            String status = rs.getString(4);
            System.out.println(id + " | " + item + " | " + price + " | " + status);
        }
    }
}

6. Updating data — executeUpdate returns how many records changed (OrderManagement):

public class OrderManagement {

    public void updateOrder() throws ClassNotFoundException, SQLException {
        Class.forName("com.mysql.cj.jdbc.Driver");                       // steps 1-3 are common
        Connection con = DriverManager.getConnection(
                "jdbc:mysql://localhost:3306/first_june", "root", "your_password");
        Statement stmt = con.createStatement();

        // step 4: an update query -> executeUpdate (not executeQuery)
        int rows = stmt.executeUpdate("update order_history set status = 'paid' where id = 2");
        System.out.println(rows + " record(s) updated");                 // 1 record(s) updated
    }
}
// In the MySQL console: select * from order_history;  -> the status has changed from hold to paid.

8. A safer version with PreparedStatement and try-with-resources (added — not shown in class):

import java.sql.PreparedStatement;

public int updateOrder(int id, String status) throws SQLException {
    String sql = "update order_history set status = ? where id = ?";   // ? = placeholders, no string gluing

    try (Connection con = DriverManager.getConnection(
                 "jdbc:mysql://localhost:3306/first_june", "root", "your_password");
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setString(1, status);          // first ?
        ps.setInt(2, id);                 // second ?
        return ps.executeUpdate();        // number of records updated
    }                                     // connection and statement are closed automatically
}

📌 Lecture Takeaways

  • JDBC lets a Java program interact with databases — a translator between Java and SQL.
  • You're a database user, not a database expert; there are 100+ databases, each with its own SQL-speaking server.
  • Every database vendor releases a language-specific driver; for MySQL + Java it's Connector/J — a JAR.
  • Add it as a Maven dependency; from now on any JAR you add comes from the Maven repository site.
  • The four steps: register the driver → create the connection → create a statement → execute SQL.
  • Class.forName("…driver class…") loads the driver dynamically (dots, not slashes); it throws the checked ClassNotFoundException.
  • Static loading (new) is decided at compile time; dynamic loading (Class.forName) at runtime — a classic interview question.
  • DriverManager.getConnection needs host, port, database, username and password; it throws the checked SQLException.
  • executeQuery returns a ResultSet: loop with next() and read columns by index starting at 1.
  • executeUpdate returns the number of records updated.
  • The console and your Java program are both clients of the same database.
  • The MySQL server runs as a Windows service — no need to start it.
  • Everything is CRUD.

🚧 Common Interview Traps

  • "Java can run SQL directly" / "the database understands Java." Neither — JDBC translates.
  • Using slashes in Class.forName. The JAR listing shows slashes; the class name uses dots.
  • Forgetting to add the connector dependency. The driver class can't be found and you get ClassNotFoundException.
  • Starting the ResultSet index at 0. JDBC column indexes start at 1.
  • Forgetting rs.next() — you must advance the cursor to read each row.
  • Thinking new doesn't load the class. Both ways load it; the difference is when the class is decided.
  • Ignoring the deprecation warning. It works, but switch to the newer driver class.
  • Using executeQuery for an update (or vice-versa). Select → executeQuery / ResultSet; update → executeUpdate / int.
  • Mixing up "driver class" and the class with main. The instructor used the word for both.
  • Building SQL with string concatenation. Added It enables SQL injection; use PreparedStatement.
  • Never closing connections. Added Use try-with-resources.
  • Trying to "start MySQL" before running the program. It's already a Windows service.
