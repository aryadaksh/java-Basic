🧠 Key Concepts

Quick Revision — ArrayList

ArrayList is index-based, uses continuous memory, and is best for random access by index (get() is O(1)). Middle insertion/removal generally requires shifting → O(N). Adding at the end can trigger resizing/data movement, so don't blindly say add() is always O(1) — always consider the actual scenario.

LinkedList — Basic Idea

A LinkedList is another List implementation, but instead of a continuous array, it's made of Nodes. Each Node stores data plus the address/reference of the next node. In a doubly linked list, each Node also stores a reference to the previous node: [previous | data | next]. Java's LinkedList is a doubly linked list.

Singly vs Doubly Linked List
  • Singly: each node knows only the next node's address — moves in one direction only (Node1 → Node2 → Node3 → null).
  • Doubly: each node knows both previous and next (null ← Node1 ↔ Node2 ↔ Node3 → null). Java's LinkedList uses this — every node has both references.
Continuous vs Non-Continuous Memory

ArrayList requires elements to sit next to each other in memory (continuous). LinkedList does NOT require this — nodes can live at completely different, random memory addresses. Each node simply stores references connecting it to the next/previous node, regardless of where they physically sit in memory.

Why LinkedList Doesn't Need Initial Capacity

ArrayList has an "initial capacity" concept because it needs to reserve a continuous memory block upfront. LinkedList has no such requirement — since it doesn't need continuous memory, each new element simply becomes a new node, connected via references to existing nodes, growing organically without any capacity planning.

Order and Duplicates — Same as ArrayList

LinkedList follows the same core List behavior: it maintains insertion order and allows duplicates. So if the requirement is just "ordered + duplicates allowed," both ArrayList and LinkedList qualify — the actual choice depends on the specific use case (covered later in this class).

Internal Node Structure

Each node in a LinkedList knows its previous and next neighbors. The first node's previous is null; the last node's next is null. Every node in between knows both its previous and next nodes. The LinkedList itself keeps a reference to the first and last nodes.

LinkedList is NOT Truly Index-Based

LinkedList methods can still accept a position, like get(2) — but this position does NOT mean the memory address can be calculated directly like an array. The index represents a logical position in the list. To actually reach that position, LinkedList must traverse through the nodes one by one.

Traversal — Moving Through Nodes One by One

You cannot directly jump from Node1 to Node5 just because Node1 exists — you must follow the chain: check Node1's next → move to Node2 → check its next → move to Node3 → and so on, until you reach the target. Finding an element at a given position generally requires this kind of traversal.

LinkedList get() — O(N)

Since LinkedList cannot directly calculate a memory address from an index, it must traverse nodes to reach the desired position — in the worst case, traveling through most/all of the list. Therefore, get(index) on a LinkedList is O(N), compared to ArrayList's O(1).

LinkedList Insertion/Deletion — Two-Part Complexity

Once you've already reached the target position/node, actually inserting or removing there just means changing a few references — no large-scale shifting like ArrayList. This link/reference change itself is O(1). BUT reaching that position in the first place (if not already known) requires traversal, which is O(N). So the overall operation, when you need to locate the position first, is O(N).

The Interview-Critical Distinction

Don't simply say "LinkedList insertion is always O(1)." The better, interview-correct explanation: "The actual node-link modification is O(1), but if we need to traverse to the target position first, the overall operation can be O(N)." This two-part breakdown is exactly what interviewers are listening for.

Why LinkedList Can Be Better for Modification-Heavy Use Cases

With ArrayList, inserting/removing in the middle of a large list means shifting many elements — expensive at scale. With LinkedList, existing nodes stay exactly where they are; only the connections between nodes change — no mass movement of data. So when frequent modification is the priority (especially if the position/node is already known or easily reachable), LinkedList can be preferable.

Creating and using a LinkedList:

import java.util.LinkedList;
import java.util.List;

class CityService {

    public List getCityNamesLinked() {
        List cities = new LinkedList<>();
        cities.add("Bangalore");
        cities.add("Chennai");
        cities.add("Hyderabad");
        cities.add("Delhi");
        cities.add("Mumbai");
        return cities;
    }

}

get() on LinkedList — O(N), requires traversal:

List cities = new LinkedList<>();
cities.add("Bangalore"); cities.add("Chennai"); cities.add("Hyderabad");
cities.add("Delhi"); cities.add("Mumbai");

String result = cities.get(4);
// Cannot jump directly to index 4's memory address like an array —

Insertion in the middle — reference changes, no shifting:

// Conceptual: inserting Node X between B and C
// Before: A -> B -> C
// After:  A -> B -> X -> C

// Only these references change:
// B.next -> X
// X.previous -> B
// X.next -> C
// C.previous -> X
// No existing data is shifted — unlike ArrayList

Deletion from the middle — reference changes, no shifting:

// Before: A -> B -> C -> D
// Remove C
// After:  A -> B -> D

// Links adjusted:
// B.next -> D
// D.previous -> B
// C itself is simply no longer referenced (eligible for garbage collection)

❓ Doubts / Questions Raised in Class

QuestionAnswer
When would you use ArrayList?When the application frequently needs random access/read by index — ArrayList is preferred since indexed access is O(1).
When would you use LinkedList?When frequent insertion/deletion is important and the required node/position can be reached efficiently — the actual link modification is O(1) and doesn't require shifting elements.
Why not use LinkedList for random access?Because LinkedList must traverse nodes to reach a position, making indexed access O(N), whereas ArrayList provides O(1) indexed access directly.
Why is ArrayList slower for middle insertion/deletion?Because it's a continuous, array-backed structure — elements must shift to preserve that continuous layout.

📌 Important Points / Common Mistakes

  • Java's LinkedList is doubly linked — every node has both previous and next references.
  • LinkedList does NOT require continuous memory, unlike ArrayList.
  • LinkedList does NOT need an initial capacity, since it doesn't reserve a continuous block upfront.
  • get(index) on LinkedList is O(N) due to required traversal — NOT O(1) like ArrayList.
  • LinkedList's actual link/reference modification is O(1), but reaching the target position (traversal) is O(N) — so state BOTH parts in interviews, not a single blanket complexity.
  • Both ArrayList and LinkedList maintain insertion order and allow duplicates — the choice between them depends on whether random access or frequent modification matters more for your use case.
