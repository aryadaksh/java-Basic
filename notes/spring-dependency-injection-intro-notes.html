🧠 Key Concepts

Where We Are

The last topic was IoC — what IoC is and what a bean is. Today the class starts Dependency Injection, and the instructor wanted students to understand what a dependency is before looking at how Spring injects it.

What Is a Dependency?

Dependency means one class (or its object) depends on another class's object. In his words: the creation of one class's object depends on another class's object.

🔥 Interview angle: "What is a dependency?" / "What is dependency injection?" — the object another class needs, and supplying that object from outside (done by Spring); see the injection card below.
The Practical Scenario — Filling in a Form

When you fill any form it takes your personal details, educational details, address and employment details. Combine all four and you get the employee details. So to create an object (bean) of EmployeeDetail, you need objects of these four classes:

Part of the formIts own class
Personal detailsa personal-details class
Educational detailsan education class
Addressan Address class
Employment / employer detailsan employment-details class
Create the Personal, Education, Address and Employment objects first
→ supplied to →
EmployeeDetail object

EmployeeDetail has a dependency on those classes: before its object can be created, the objects of the classes it depends on are created, and then those objects are injected into it. "Very simple."

The Same Idea in Code Terms — Employee and Address
  • An Employee class holds the employee's information — first name, last name, employee code and so on — and the employee also has an address.
  • The address is its own class, with fields such as line one, area, city, state and country (some of the field names were garbled in the recording).
  • To create an Employee object you must initialise the Address first and provide it as a dependency. The instructor ended by saying that when you create the object of the employee class you need the address object as well — the point where a constructor comes into play (the word itself is unclear in the recording).
Why Separate Classes? — The Modular Approach
  • Students may ask: "why not put everything in one class?" His answer: always follow a modular approach.
  • An address alone has many fields; there's no point keeping them inside the employee class. Education details could be another ~20 fields.
  • So put the address fields in an address class and the education fields in their own class: these fields hold the address, those hold the basic employee details — and the employee then has an address.
Injection — Who Provides the Objects?
  • The objects the class needs are injected into it. Providing the object is the injection — the instructor called the one who provides it the "injector".
  • This is taken care of by the Spring Framework — which is why Spring is the next step after IoC.
  • The order matters: create the dependency objects first, then the object that needs them.
💡 Added clarification:
  • Terms: the class that needs the object is the dependent; the needed object (Address) is the dependency; handing it over is injection; Spring's IoC container is the injector doing it.
  • Why it matters: without injection Employee would create its own Address with new inside, which ties the two tightly together. Supplying it from outside is loose coupling — the idea you met as constructor injection in the project reviews.
  • Types of injection — constructor, setter and field — exist in Spring, but this recording doesn't reach them (the instructor was just at the constructor idea).

💻 Code Snippets / Examples

Note on this code: the instructor explained this verbally and showed no code in this transcript, so both snippets are my illustrations of what he described — the field names and values are mine. The second snippet is a preview of Spring's side, which this recording does not cover.

1. Plain Java — Employee depends on Address, so the Address must exist first:

public class Address {
    private String line1, area, city, state, country;

    public Address(String line1, String area, String city, String state, String country) {
        this.line1 = line1; this.area = area; this.city = city;
        this.state = state; this.country = country;
    }
}

public class Employee {
    private String firstName, lastName, employeeCode;
    private Address address;                 // Employee DEPENDS on an Address object

    public Employee(String firstName, String lastName, String employeeCode, Address address) {
        this.firstName = firstName;
        this.lastName = lastName;
        this.employeeCode = employeeCode;
        this.address = address;              // the dependency is supplied from outside
    }
}

public class App {
    public static void main(String[] args) {
        // 1. create the dependency first
        Address address = new Address("12 MG Road", "Camp", "Pune", "Maharashtra", "India");
        // 2. then the object that needs it - the address object is "injected" through the constructor
        Employee emp = new Employee("Asha", "Rao", "E101", address);
    }
}

2. Preview (added) — the same wiring done by the Spring container with Java configuration:

@Configuration
public class AppConfig {

    @Bean
    public Address address() {
        return new Address("12 MG Road", "Camp", "Pune", "Maharashtra", "India");
    }

    @Bean
    public Employee employee(Address address) {      // Spring supplies the Address bean here
        return new Employee("Asha", "Rao", "E101", address);
    }
}
// Nobody calls "new Employee(..., address)" in main: the container creates the Address bean first
// and injects it into the Employee bean - exactly the dependency + injection idea above.
