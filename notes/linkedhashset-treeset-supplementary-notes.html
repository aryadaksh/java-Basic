🧠 Key Concepts

Recap: HashSet's Trade-off

HashSet gives you fast, hash-based uniqueness checking (O(1) average) — but sacrifices any predictable ordering. Iteration order depends on internal bucket placement, not insertion sequence.

LinkedHashSet — Uniqueness + Insertion Order

LinkedHashSet extends HashSet and adds ONE guarantee HashSet lacks: it maintains insertion order during iteration. Internally, it combines a hash table (same bucket/hashCode mechanism as HashSet, for fast lookups) with an additional doubly linked list running through all entries, threading them together in the order they were inserted.

Why LinkedHashSet Costs a Little More

Maintaining that extra linked list means slightly more memory overhead and marginally more bookkeeping per insertion compared to plain HashSet — but lookup/insertion/removal are still effectively O(1) average, same as HashSet. The trade-off is worth it whenever predictable iteration order matters.

When to Use LinkedHashSet

Choose LinkedHashSet when you need BOTH: (1) no duplicates, AND (2) elements returned in the exact order they were added — e.g. displaying a user's recently viewed items with duplicates removed, but still showing them in the order they were first viewed.

TreeSet — Uniqueness + Sorted Order

TreeSet implements NavigableSet (which extends SortedSet). Unlike HashSet/LinkedHashSet, it is NOT backed by a hash table — it's backed by a Red-Black Tree (a self-balancing binary search tree). Elements are always kept in sorted order — either their natural order, or an order you define.

Natural Ordering — Comparable

For TreeSet to sort elements automatically, the element's class must implement Comparable and define compareTo() — this is how built-in types like Integer, String, etc. already support natural sorting (numeric order, alphabetical order). For custom classes, you must implement this yourself to define what "sorted" means for that type.

Custom Ordering — Comparator

If you want a DIFFERENT sort order than the class's natural one (or the class doesn't implement Comparable at all), you can supply a Comparator when creating the TreeSet — a separate object defining the exact comparison logic to use instead.

TreeSet Does NOT Allow null

Since TreeSet must be able to COMPARE every element against others to maintain sorted order, adding null throws a NullPointerException — there's no meaningful way to compare null against a real value using compareTo().

Critical Nuance: TreeSet Uses compareTo() for Duplicates, NOT equals()/hashCode()

This is a genuinely important distinction from HashSet/LinkedHashSet: TreeSet determines whether two elements are "the same" (duplicate) based on whether compareTo() returns 0 — NOT based on equals()/hashCode(). This means it's technically possible for compareTo() to return 0 for two objects that equals() would consider different — TreeSet would treat them as duplicates regardless of what equals() says. Always ensure your compareTo() logic is "consistent with equals" (returns 0 exactly when equals() would return true) to avoid confusing, inconsistent behavior across different collection types.

TreeSet's Time Complexity

Since TreeSet is backed by a balanced tree (not hashing), operations like add(), remove(), and contains() are O(log N) — slower than HashSet's average O(1), but you gain guaranteed sorted order as a result. This is the classic time-vs-ordering trade-off.

TreeSet Navigation Methods (NavigableSet)

Because it's a sorted structure, TreeSet offers powerful navigation methods not available on HashSet/LinkedHashSet:

  • first() / last() — smallest/largest element
  • higher(e) / lower(e) — strictly greater/smaller than e
  • ceiling(e) / floor(e) — greater-or-equal / smaller-or-equal to e
  • headSet(e) / tailSet(e) — elements before/after a given point
  • pollFirst() / pollLast() — retrieve and remove the smallest/largest element

💻 Code Snippets / Examples

LinkedHashSet — preserves insertion order:

import java.util.LinkedHashSet;
import java.util.Set;

class Driver {
    public static void main(String[] args) {
        Set cities = new LinkedHashSet<>();

        cities.add("Mumbai");
        cities.add("Delhi");
        cities.add("Bangalore");
        cities.add("Mumbai"); // duplicate, ignored

        for (String city : cities) {
            System.out.println(city);
        }
        // Output: Mumbai, Delhi, Bangalore
        // — EXACT insertion order, unlike HashSet
    }
}

TreeSet — natural (sorted) ordering with built-in types:

import java.util.TreeSet;
import java.util.Set;

class Driver {
    public static void main(String[] args) {
        Set numbers = new TreeSet<>();

        numbers.add(50);
        numbers.add(10);
        numbers.add(30);
        numbers.add(10); // duplicate, ignored

        for (int n : numbers) {
            System.out.println(n);
        }
        // Output: 10, 20... wait, 10, 30, 50 — always sorted ascending
    }
}

TreeSet with custom objects — implementing Comparable:

class Employee implements Comparable {
    int id;
    String name;

    public Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public int compareTo(Employee other) {
        return Integer.compare(this.id, other.id); // sort by id ascending
    }

    @Override
    public String toString() {
        return id + " - " + name;
    }
}
Set employees = new TreeSet<>();
employees.add(new Employee(103, "Kodewala"));
employees.add(new Employee(101, "Devwin"));
employees.add(new Employee(102, "Anita"));

for (Employee e : employees) {
    System.out.println(e);
}
// Output: 101 - Devwin, 102 - Anita, 103 - Kodewala — sorted by id

TreeSet with a custom Comparator (different sort order):

import java.util.Comparator;
import java.util.TreeSet;

Set byName = new TreeSet<>(new Comparator() {
    @Override
    public int compare(Employee a, Employee b) {
        return a.name.compareTo(b.name); // sort alphabetically by name instead
    }
});

byName.add(new Employee(103, "Kodewala"));
byName.add(new Employee(101, "Devwin"));
byName.add(new Employee(102, "Anita"));
// Iteration order now: Anita, Devwin, Kodewala

TreeSet navigation methods:

TreeSet scores = new TreeSet<>();
scores.add(10); scores.add(25); scores.add(40); scores.add(55);

System.out.println(scores.first());      // 10
System.out.println(scores.last());       // 55
System.out.println(scores.higher(25));   // 40 (strictly greater than 25)
System.out.println(scores.ceiling(30));  // 40 (smallest >= 30)
System.out.println(scores.floor(30));    // 25 (largest <= 30)

The compareTo() vs equals() nuance — a subtle bug source:

class Product implements Comparable {
    String name;
    double price;

    public Product(String name, double price) {
        this.name = name;
        this.price = price;
    }

    @Override
    public int compareTo(Product other) {
        return Double.compare(this.price, other.price); // sorts by price ONLY
    }
    // equals()/hashCode() not overridden — uses default identity-based behavior
}
Set products = new TreeSet<>();
products.add(new Product("Mouse", 500));
products.add(new Product("Keyboard", 500)); // SAME price -> compareTo() returns 0

System.out.println(products.size());
// Output: 1 — "Keyboard" was treated as a duplicate of "Mouse" by TreeSet,
// purely because compareTo() returned 0 (same price), even though
// they are clearly DIFFERENT products by equals()/name.
// This is why compareTo() should be "consistent with equals" when possible.

❓ Likely Interview Questions

QuestionAnswer
What's the difference between HashSet and LinkedHashSet?Both guarantee uniqueness with similar average performance; LinkedHashSet additionally preserves insertion order via an internal doubly linked list, while HashSet's iteration order is unpredictable (bucket-based).
Why is TreeSet slower than HashSet for add()/contains()?TreeSet is backed by a Red-Black Tree, giving O(log N) operations, since it must maintain sorted order — HashSet's O(1) average comes from hash-based bucket placement with no ordering guarantee.
Does TreeSet use equals()/hashCode() to detect duplicates?No — it uses compareTo() (or a supplied Comparator); if compareTo() returns 0 for two objects, TreeSet treats them as duplicates, regardless of what equals() would say.
Can you add null to a TreeSet?No — attempting this throws a NullPointerException, since TreeSet must compare every element to maintain sorted order, and null has no meaningful comparison.
How do you sort a TreeSet in a custom (non-natural) order?Supply a Comparator when constructing the TreeSet, defining your own comparison logic instead of relying on the class's compareTo().

📌 Important Points / Common Mistakes

  • LinkedHashSet trades a small amount of memory/overhead for predictable insertion-order iteration.
  • TreeSet is NOT hash-based — it's a Red-Black Tree, giving O(log N) operations instead of O(1) average.
  • TreeSet determines uniqueness via compareTo() == 0, not equals()/hashCode() — a subtle but important distinction from HashSet/LinkedHashSet.
  • Always aim for compareTo() to be "consistent with equals" to avoid confusing behavior when the same objects are used across different collection types.
  • TreeSet does not allow null elements — HashSet and LinkedHashSet do (one null each).
  • Choose based on your actual requirement: pure uniqueness (HashSet), uniqueness + insertion order (LinkedHashSet), or uniqueness + sorted order (TreeSet).
