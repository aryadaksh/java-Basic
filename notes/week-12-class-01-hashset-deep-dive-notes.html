🧠 Key Concepts

HashSet Internal Structure — Recap

By default, HashSet capacity is 16. Internally it creates an array of buckets. Each bucket has its own independent linked-list structure — there is NOT one single linked list shared across all buckets; every bucket manages its own chain.

The Full hashCode → Bucket Flow

When add() is called: hashCode() is computed for the element → a spread operation is applied (further mixing the bits for better distribution) → a bitwise AND operation is applied → this produces the final bucket index.

hash & (n - 1)   // n = capacity

// For capacity 16:
hash & 15   // always produces a number from 0 to 15
Duplicate vs Hash Collision — The Full Decision Flow
  1. Bucket is empty → add the element directly. No collision.
  2. Bucket already has an element → call equals().
  3. equals() returns true → it's a genuine duplicate → HashSet does NOT add it.
  4. equals() returns false → the elements are different but landed in the same bucket → this is a hash collision → a new node is added to that bucket's linked list.
Hash Collision Example

Suppose "Bangalore" and "Chennai" both compute to bucket 8, despite being different elements. Bucket 8 then holds a small linked list: Bangalore → Chennai → null. Multiple colliding elements are chained together this way.

HashSet Uses HashMap Internally

HashSet's job is to maintain unique elements; HashMap stores key-value pairs. But whether you're learning "how HashSet works" or "how HashMap works," the underlying hashing/bucket mechanism is essentially the same.

Why HashSet is Unordered

Elements are placed according to their calculated bucket position, not insertion sequence. Example: "iPhone 17" → bucket 14, "Samsung" → bucket 3, "LG" → bucket 8. When reading the set back, elements may appear in bucket order, not the order you added them. The goal is good time complexity for add/check operations — NOT preserving insertion order.

HashSet Has No get() — Only contains()

A Set holds standalone elements, not key-value pairs — so there's no "key" to fetch a "value" by. (Contrast: HashMap has get("Karnataka") returning "Bangalore" because it stores key→value pairs.) Since HashSet just needs to answer "is this element present?", it provides contains(element) instead.

How contains() Actually Works

Calling products.contains("iPhone 17"): (1) compute hashCode of "iPhone 17". (2) apply the same bucket calculation used during add(). (3) identify the target bucket. (4) go directly to that bucket. (5) search the linked list inside it. If found → true. If the end of the chain (null) is reached without a match → false.

Time Complexity — Best Case vs Worst Case

Best case: O(1) — the bucket has zero or one element, so the check is immediate. Worst case: O(n) — where n is the number of elements in that SPECIFIC bucket's collision chain, NOT the total size of the HashSet. Example: total elements = 1000, but bucket 100 has only 10 colliding elements → a search landing in bucket 100 is O(10), i.e. O(n) for that bucket's chain specifically. Don't say "O(n) because the HashSet has n elements" — that's imprecise; explain it in terms of the specific bucket's chain length.

add() Return Value — boolean

HashSet.add() returns true if the element was successfully added, and false if it was already present (a duplicate). This return value is directly useful for detecting duplicates in code without a separate contains() check.

Load Factor and Threshold

Load Factor (default 0.75, i.e. 75%) determines how "full" the table can get before it needs to grow. Threshold = capacity × load factor. For capacity 16: 16 × 0.75 = 12. So the table can hold up to 12 elements comfortably; adding the 13th element crosses the threshold and triggers growth.

Rehashing — What It Is

When capacity increases, the bucket formula itself changes: old capacity 16 → hash & 15; new capacity 32 → hash & 31. Since the FORMULA'S INPUT (capacity) changed, an element that was previously in one bucket may now need to move to a different bucket under the new formula. Java must therefore redistribute all existing elements according to the new capacity — this redistribution process is called rehashing.

What Happens During Rehashing — Step by Step

Suppose the 13th element crosses the threshold (16 → 32). For every existing element: (1) use its hash information again, (2) apply the NEW bucket calculation (now using 32 as capacity), (3) identify its new bucket, (4) move it there.

Why Rehashing is Expensive

Rehashing requires processing and redistributing ALL existing elements — not just the new one being added. This is genuinely costly at scale. Practical tip: if you already know roughly how many elements you'll store (e.g. ~1000), it's beneficial to specify an appropriate initial capacity upfront, avoiding repeated resize/rehash cycles as the set grows from the small default.

Important Nuance: Different hashCodes CAN Land in the Same Bucket

Two elements can have genuinely different hashCode values (X ≠ Y) and STILL land in the same bucket — because the bucket index is constrained by capacity (e.g. only 0–15 possible values for capacity 16). Many different hashCode values can map to the same final bucket index through the AND operation. Key nuance: "same bucket" does NOT necessarily mean "same hashCode" — a bucket collision can happen even when hashCodes genuinely differ, purely due to how the modulo-like AND operation compresses a huge range of possible hashCodes into a small number of buckets.

💻 Code Snippets / Examples

add() return value for detecting duplicates:

import java.util.HashSet;
import java.util.Set;

class Driver {
    public static void main(String[] args) {
        Set set = new HashSet<>();

        boolean r1 = set.add("A"); // true — newly added
        boolean r2 = set.add("A"); // false — already present (duplicate)

        System.out.println(r1); // true
        System.out.println(r2); // false
    }
}

contains() usage:

Set products = new HashSet<>();
products.add("iPhone 17");
products.add("Mac Pro");
products.add("Samsung");

boolean exists = products.contains("iPhone 17"); // true
// Internally: hashCode("iPhone 17") -> bucket calculation -> go to that bucket

The bucket formula, and how it changes on resize:

// Capacity 16
int bucketIndex = hash & (16 - 1); // hash & 15 -> range 0-15

// After rehashing, capacity 32
int newBucketIndex = hash & (32 - 1); // hash & 31 -> range 0-31
// Same hash, but DIFFERENT bucket possible, since the AND mask changed

Specifying initial capacity to avoid repeated rehashing:

// If you expect ~1000 elements, avoid growing from the tiny default (16)
Set largeSet = new HashSet<>(1024); // initial capacity hint, reduces rehash cycles

🎤 Interview-Ready Answer: "How Does HashSet Work Internally?"

"When we add an element to a HashSet, internally HashSet uses a HashMap. The hashCode() of the incoming element is calculated first. Using the hash code, the bucket is identified using the hashing logic. JVM then checks the identified bucket.

If the bucket is empty, the element is directly stored there.

If an element already exists in that bucket, equals() is used to compare the incoming element with the existing element.

If equals() returns true, the element is considered a duplicate and is not added.

If equals() returns false, it is considered a hash collision. A new node is created in the existing bucket's linked-list structure and the new element is stored there.

The default capacity is 16 and the default load factor is 0.75. Therefore, the initial threshold is 12. When the threshold is crossed, the capacity increases and rehashing occurs. During rehashing, elements are redistributed according to the new capacity."

📌 Important Points / Common Mistakes

  • Every bucket has its OWN linked list — not one shared linked list for the whole HashSet.
  • Duplicate = same bucket + equals() true. Hash collision = same bucket + equals() false.
  • HashSet has no get(); use contains() to check for element presence.
  • Worst-case time complexity is O(n) where n is the specific bucket's chain length, not the total set size — always phrase it this way in interviews.
  • add() returns a boolean — true if newly added, false if it was a duplicate.
  • Default load factor is 0.75; threshold = capacity × load factor.
  • Crossing the threshold triggers capacity doubling AND rehashing (redistributing every existing element).
  • Rehashing is expensive — provide an initial capacity if the approximate final size is known in advance.
  • Different hashCodes CAN still map to the same bucket — don't assume same bucket implies same hashCode.
